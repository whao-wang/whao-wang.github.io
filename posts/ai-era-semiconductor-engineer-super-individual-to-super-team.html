02 / LLM

02 / LLM VS 工程问题

LLM 基于大量数据做模式识别和拟合，本质是概率与逼近；而工程设计需要可靠性、可验证性、可重复性，以及对边界条件的掌控。

这就是两者的本质矛盾：工程问题需要证据，不能只需要“看起来合理”的答案。
Coding 是目前我们找到的第一个、足够复杂、反馈又足够明确的通用问题空间。 它不是在训练 AI 写代码。它是在训练 AI 解决问题。
HUMAN定义问题与约束
→
LLM生成候选方案
→
TOOLS仿真 / 编译 / 测试
后来：工具验证 → LLM 修改 → 人做最终判断。Coding 是目前最清晰的通用问题空间。

半导体超级团队：
围绕一个 Block 或收敛目标，把人、Agent 与 EDA 工具链接成闭环

规格 / PPA 目标 → Agent + EDA 执行 → 仿真 / 规则 / Regression 反馈 → 专业 Sign-off → 经验沉淀
模块 / 场景牵头人明确规格、PPA目标、边界条件和收敛标准。
设计工程师负责电路、RTL、约束以及关键设计取舍。
验证 / Sign-off用仿真、Coverage、STA、DRC/LVS提供证据。
EDA / 平台工程师打通工具、脚本、License、算力和运行环境。
AI 工程师把领域方法编排成可执行、可评测的 Agent。
测试 / 硅后工程师用ATE、Fail Signature和硅数据补上物理反馈。

一个设计场景如何跑通

01
选一个收敛卡点如PPA、Coverage、Regression或DRC热点。
02
定义Baseline明确当前周期、质量、Golden Case与退出条件。
03
接入真实工具链让Agent读取状态、调用EDA并解析结果。
04
在真实Block验证工程师处理例外并完成最终Sign-off。
05
跨项目复用沉淀脚本、知识、评测集与失败样本。
